# 运行与提醒

[返回 README](../README.md)

## 更新节奏与调度状态

当前仓库默认业务节奏：

| 任务 | 北京时间 | 工作内容 |
| --- | --- | --- |
| 每日更新 | 每天 21:00 启动 | 处理并发布资讯，刷新模型榜单，再分发今日热点与活动提醒 |
| 节目更新 | 每小时整点检查 | 检查已关注节目；有符合条件的新一期时发送提醒 |

21:00 是启动时间，发布和发送在处理完成后发生，不保证恰好 21:00 送达。仅修改提醒配置不会自动修改平台上的 Cron；更改节奏需同时核对调度表达式、业务时间校验和交付配置。

独立 Cloudflare 调度器位于 [`scheduler/`](../scheduler/)，使用 Cron 启动 Workflow；Workflow 按需推进后台批次，完成即结束，不需要每 5 分钟固定轮询。

仓库的安全默认值为 `probe`，业务归属默认 `legacy`。这些值用于迁移前验证，**不表示独立调度已经接管生产**。是否已部署、启用和完成验收，应查询平台配置及真实运行记录。完整步骤见 [独立调度说明](../scheduler/README.md)。

单独更换调度器不会改变网站域名；只有迁移网站托管或另行配置域名，才涉及访问地址调整。

## 后台入口

| 入口 | 用途 | 访问要求 |
| --- | --- | --- |
| `GET /api/state` | 读取公开资讯、来源状态与发布结果 | 公开只读 |
| `GET /api/pipeline` | 处理进度与当日预算；`?item=条目ID` 查看单条记录 | 管理员鉴权 |
| `POST /api/pipeline` | 单独运行阶段、处理指定条目或推进小批次 | 管理员鉴权 |
| `GET /api/refresh` | 日更入口的当前调用说明 | 公开说明 |
| `POST /api/refresh` | 原日更入口，按保存的游标续跑 | 管理员鉴权及调度归属校验 |
| `GET/POST /api/subscriptions/refresh` | 原节目检查入口；GET 返回说明或受保护的汇总状态 | 写入与状态查询需要管理员鉴权 |
| `GET/POST /api/scheduler` | 独立调度状态、推进任务与归属控制 | 调度密钥或管理员密钥，权限按操作区分 |

管理员认证通过 `Authorization: Bearer <ADMIN_TOKEN>`。独立调度使用专用 `SCHEDULER_TOKEN`，不能用它修改归属或重处理内容。若托管平台另有访问控制，应按部署平台要求处理；业务密钥仅在服务端保存和传输。

阶段请求体示例（向 `POST /api/pipeline` 提交 JSON）：

```json
{"stage":"analyze"}
```

也可以指定 `itemIds` 处理少量条目；`reprocess` 会重置选中条目的处理状态并保留旧分析与归属记录。它用于有明确依据的内容修正，不能用来绕过预算或未知调用回执。

自动任务每次只推进有界工作量。`busy`、`blocked`、`skipped`、授权错误和部分完成有不同含义，应按对应入口说明停止、续跑或人工处理；不要把任意 HTTP 200 当成整轮成功。

## 怎样确认更新真的成功

一次完整验收应把以下证据对应到同一业务轮次：

1. 平台上确实发生了预定时间的触发，并有对应的任务 ID。
2. D1 中有实际处理记录，阶段、失败来源和待处理数量可检查。
3. `GET /api/state` 读到了新的发布快照，页面能显示相应内容。
4. 若本轮有应发送内容，核对发送回执与飞书群中的实际消息。

创建定时任务、部署成功、单元测试通过，都不能代替真实定时验收。`complete=true` 也要结合待处理、失败来源和发送回执判断；预算耗尽时可能已发布部分结果，但仍留有积压。

## 节目与飞书提醒

### 关注节目

在网站「我的关注」中提交 Apple Podcasts 节目链接、YouTube 频道链接，或支持的公开 RSS，识别后确认关注。

- Apple 节目通过已知 RSS 映射或官方 Lookup 接口解析；接口受限时可改用该节目的公开 RSS。
- YouTube 支持频道 ID 和可解析的 `@handle` 主页。单个视频链接不是频道订阅入口。
- 小宇宙主页和未支持的托管域名不保证可识别；以界面返回的结果为准。
- 当前每个浏览器最多关注 40 个节目。新关注可浏览最近内容，但只提醒关注之后发布、且在最近 7 天内的新一期。

### 连接飞书

1. 在飞书群设置中添加自定义机器人，取得 Webhook；如启用签名校验，同时准备签名密钥。
2. 在网站「提醒设置」连接机器人。
3. 选择节目更新、今日热点和活动提醒中的所需类别，开启提醒并保存。
4. 使用预览或测试功能核对内容，再确认群内实际收到消息。

仅保存 Webhook 不会自动开启发送。手动分发先预览，发送的应是同一份预览内容；当前预览有效期为 30 分钟。

各浏览器使用随机访问凭证管理自己的关注与提醒，服务器保存凭证摘要；飞书 Webhook 与签名密钥加密保存。清除浏览器数据会失去对原设置的访问，所以应先关闭不再需要的推送。收藏也保存在当前浏览器，暂不提供账户同步。

### 发送与回执

日更使用本轮已发布的热点与活动结果；节目更新独立检查，不等待日更，也不额外调用模型写摘要。无新增内容时不发送。

长内容会拆成多条消息，后台分批推进。发送前记录持久化状态，以降低重复推送风险；未收到明确回执时标记为待核对，不自动重发。网络超时或未知状态应先核对群内消息，再决定后续处理。

活动提醒使用已核验的时间与状态，在首次发现、日程变更或临近开始 / 截止时按规则发送；不猜测缺失日期。规则见 [`config/delivery.mjs`](../config/delivery.mjs) 及活动处理代码。

## 异常处理

| 情况 | 处理原则 |
| --- | --- |
| 单个来源失败 | 保留已有内容，记录失败原因和最近成功时间 |
| 模型预算不足 | 保留待处理条目，下次续跑，不绕过预算限制 |
| 模型调用费用未知 | 先核对调用回执与平台账单，不直接重复请求 |
| 飞书回执未知 | 核对群消息与记录，避免重复推送 |
| 定时器已部署但数据未变 | 检查模式、任务归属、真实触发、后台进度及发布快照 |
| 调度迁移失败 | 按调度文档恢复原归属与原任务，保留业务游标和去重记录 |

排查和反馈时只使用必要的脱敏状态；不在公开 Issue、截图或日志中附上读者凭证、模型密钥、飞书 Webhook 或签名密钥。

## 飞书卡片模板

今日热点、活动和我的关注均每条内容发送一张 interactive 卡片，依次展示标题、来源与北京时间发布时间、已有内容提取的 1–2 句要点，以及阅读原文按钮。活动继续显示时间、地点、截止时间。标题和要点仅作展示压缩，不新增模型调用；卡片不会改变筛选、排序、定时调度或通知 ID。

旧版长文本保存的逐条 notices 继续有效，不因模板升级重发已通知内容。每日和关注仍使用原有分批续跑、机器人发送间隔和明确回执规则；每张卡片单独记录发送结果。手动预览保存卡片内容，点击发送使用同一份快照。
