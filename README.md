# DayDay AI

每天一点，跟上 AI。免费阅读，无需注册。

## 当前阶段

第一阶段：按用户三张截图中的来源，接入公司 Blog / 技术报告 / 产品发布、论文与研究、媒体资讯、Newsletter、开发者平台、线上发布会、线下活动、投融资、招聘和政策监管。

第二阶段：粘贴 Apple Podcasts 节目、YouTube 频道或支持的公开 RSS → 识别 → 确认关注 → 查看更新并前往原平台。没有“发现节目”。

第三阶段：访客自行连接飞书自定义机器人，可选择我的关注更新、每日今日热点及活动提醒；支持预览、下载文本、手动发送和发送回执。默认关闭发送，必须连接机器人并主动开启。没有复用 Dify 内的私人机器人。

## 阅读与数据

- 今日热点：首次报道在近 24 小时内的事件综合排名，非社媒流量热度；不把职位记录放进热榜。
- 主题：分类 → 搜索 / 来源 / 语言 / 排序；公司动态可再按 Blog、技术报告、产品发布筛选。
- 每日简报 / 周报：按北京时间选择日期，展示已落库的模型要点，按重要性选稿。
- 收藏：当前浏览器 localStorage，无需账户，不跨设备同步。清空浏览器数据会清空收藏。
- 信息源：展示已接通、更新异常、待接入和检查时间；每条原文都可追溯。
- 同一个发布者的 Blog、研究、SDK、模型端点不会重复增加首页发布者计数。最近 48 小时检查成功才计为正常。
- 招聘来源为用户指定公司的官方招聘端点；“职位更新”不当作原始发布日期。模型元数据标记“模型创建”，不冒充官方发布公告。
- 仅采集公开摘要。付费、私域、个人邮箱和群聊不在自动读取范围内。

## 采集与处理（v3）

保留 Workers + D1。后台按 collect → analyze → deduplicate → group → score → publish 分批执行；公开页面和 `/api/state` 只读取 D1 `news_publication_v3` 快照，不调用采集、模型、归组或评分。每个阶段可通过受保护的 `POST /api/pipeline` 单独运行，JSON 参数为 `{"stage":"analyze"}` 等；`GET /api/pipeline` 返回进度和当日预算，`?item=条目ID` 查看单条分析与阶段记录。公开访问这些管理接口返回 401。

- `pipeline_items` 保存有界原始摘要、模型分析、去重指向、事件归属和状态；`pipeline_steps` 保存阶段结果与配置版本；`pipeline_events` 分列保存热度、重要性、时效、可靠性。
- 规则只过滤明显促销和明确无关内容；没有 AI 关键词本身不作为丢弃理由。模型逐条独立输出中文标题、一句话要点、最多3条摘要、是否相关、0–100重要性及依据，不得借用同批其他条目事实。原始摘要不经公开接口或页面返回，不转载全文。
- 去重使用规范链接与完全相同内容；事件候选由实体和文本召回，再由模型结合原始标题、日期和有界摘要区分同一事件/后续进展/新事件。每个候选最多保留2条来源证据，每条摘要最多900字符。未使用向量服务。报道角度、公告细节、名称缩写、报道日期不同本身不产生新事件；有明确的新现实动作才算后续。低置信度保持独立，并记录候选、阈值及未合并原因。
- 指定样本可用 `{"stage":"analyze","itemIds":["条目ID"]}`，也支持 deduplicate/group，单次最多6条。`{"stage":"reprocess","itemIds":["条目ID"]}` 仅重置指定的非归档条目，保存旧分析和事件归属，再按 analyze→deduplicate→group→score→publish 重跑。旧公开快照在 publish 前保留。自动任务不会调用 reprocess。相同版本相同请求复用调用回执；修订提示词需更新配置版本。
- 热度是48小时内去重后的独立发布者数量，重复转载及同发布者多个端点不重复加分。热点范围为首次发布24小时内，按热度排序；日报按模型重要性排序，默认入选线60分。四项分开存储，没有综合总分。
- 模型、提示词、分批数量、阈值、公式和价格集中在 `config/pipeline.mjs`。服务器密钥为 `DEEPSEEK_API_KEY`，仅在 Sites 环境密钥中配置，禁止写入代码、日志、提示词或客户端。
- 每日预算人民币6元，按北京时间自然日。使用2026-10-24核验的 Flash 高峰价格保守记账：输入2元/百万token、命中缓存0.04元、输出8元。调用前按最大输入与输出原子预留；收到 usage 后核算；超时等结果不明的调用保留预留金额，阻止自动重复调用。平台实际离峰费用可能更低，其他应用使用同一密钥的费用不在本网站账本内。
- `pipeline_calls` 保存调用哈希、状态、token用量、费用和响应回执。数据写入失败后可复用已存响应；余额不足保留待处理内容，下一次任务继续。修改模型或价格前需重新核验价格并更新配置版本。
- 来源状态保存在 `settings.news_health`，含最近检查、最近成功时间及失败原因。失败不清空已有内容。种子目录及数据库旧条目首次导入，超过14天的原始条目标记归档，不自动消耗模型预算；旧日报保留标题和链接，不把旧原文摘要冒充为新模型要点。
- 当前用 D1 游标、租约和小批次续跑，无额外队列。每阶段最多6条，每次模型请求只处理1条，避免跨条目事实污染和候选ID串用；归组使用请求内短编号，服务器校验后映射回真实事件。每阶段运行25秒后不再启动新请求，进行中的请求最长45秒，剩余条目下次续跑；目标处理返回 remainingSelected。单条无效结果不影响其他条目。分析/归组输出上限分别1200/700 token。自动调用每次贯穿一小批分析→去重→归组→评分→发布，历史积压不会阻塞最新结果展示；每个阶段均写 runs。不明费用需先核对回执，不能直接重复付费请求。

## 线上更新

现有 Sites 项目 ID 保存在 `.openai/hosting.json`，必须复用。旧版共享的个人关注、收藏、提醒、反馈不再通过公开接口返回，旧 `POST /api/action` 返回 410。

- `GET /api/state`：公开只读资讯、源列表和状态，不含私人数据或密钥。
- `GET /api/refresh`：无密钥的后台任务调用说明。
- `POST /api/refresh`：需服务器 `ADMIN_TOKEN`，未授权返回 401；不接受自定义 URL 或数据。
- 每次更新运行一小批完整处理链；返回 `complete=true` 表示处理并发布完成，不能把采集完成当作整轮完成。
- 更新后必须重新读取 `GET /api/state` 验证 `collectedAt` 和 `health`，不能把成功触发任务当作成功采集。
- 现有早8点、晚8点任务应复用，不重复创建。公开版调用必须同时提供 Sites 服务访问头和应用授权头。已将本站的 Sites 服务凭证作为服务器 `ADMIN_TOKEN`；只能从当前 Site 的 `get_site` 临时获取，不能写进提示词、源码、日志或浏览器。凭证若被平台轮换，需要重新配置服务器密钥。
- 独立 Cloudflare 部署时，生成独立的强随机 `ADMIN_TOKEN`，绑定 D1，并配置 Cron 调用 Worker 的 `scheduled` handler。当前代码包含 handler，但没有自行声称 Cloudflare Cron 已启用。

### 已有云任务的执行说明

仅更新第一阶段公共资讯，不采集节目，不发送提醒。先 GET `/api/refresh` 读取当前说明；从本站 `get_site` 获取服务凭证，仅对本站发送 `OAI-Sites-Authorization: Bearer ...` 和 `Authorization: Bearer ...`。依次 POST，直到 `complete=true`，先以 GET `/api/refresh` 返回的最新阶段与上限说明为准（最多400次；达到上限则保留游标，报告未完成）；遇 `busy=true` 停止，遇错误保留原数据并报告。最后 GET `/api/state`，报告检查结果。不要记录凭证，不重复部署，不修改源清单。

## 节目关注及提醒

- 每个浏览器生成随机 256 位访问凭证并保存在 localStorage，仅通过 Authorization 发送到本站。服务器存储不可逆摘要；各浏览器只访问自己的关注、配置和回执，不需要注册，也不跨浏览器同步。清除浏览器数据前应先关闭提醒，否则会失去对原设置的访问。
- `GET/POST /api/subscriptions` 是浏览器专属接口；机器人地址和签名密钥永不返回客户端。`REMINDER_ENCRYPTION_KEY` 是 Sites 服务器端的 32 字节十六进制密钥，用 AES-GCM 加密机器人配置，禁止写入源码或日志。不要随意轮换，否则已有配置将无法解密。
- 新关注会读取最近节目供浏览，但只提醒发布时间晚于关注时间的新内容。每个浏览器最多关注 40 个节目；读取最近 18 期，页面显示最近 100 条，提醒只覆盖最近 7 天。
- 支持常见公开播客托管服务；逐次验证重定向并限制响应大小。你提供的 25 个播客保存了按 Apple 节目 ID 匹配的公开 RSS 映射（原始目录及 `data/podcast-links.json`）；其他 Apple 节目通过官方 Lookup API 解析 RSS，云端接口返回 403 时明确提示改用 RSS，不声称识别成功。YouTube 支持频道 ID 和可解析的 @handle 主页。小宇宙主页及其他未支持的 RSS 托管域名会明确报错，需要同一节目的 Apple / RSS 链接；不能宣称任何链接均可识别。
- 节目失败保留原内容并标注错误。手动检查间隔 5 分钟；自动节目检查独立每 30 分钟运行一次，有新一期就发送；热点和活动在每天北京时间 21:00 网站更新完成后合并分区推送一次。只向主动连接机器人并开启相应类别的读者发送。
- 飞书发送先写持久化声明再发送，同一条节目只发送一次。未收到明确回执时标为待核对，不自动重试；失败和回执可在提醒设置查看。手动分发必须先预览，并发送同一份预览文本，预览有效期 30 分钟。
- 关注更新基于真实节目记录；资讯简报只分发现有处理结果，不在发送时再次调用模型。

### 节目更新后台任务

每小时 :00、:30（Asia/Shanghai）调用 `/api/subscriptions/refresh`。先 GET 读取接口说明，再使用服务凭证顺序 POST `{}` 到 `complete=true`，每次运行最多 100 次；遇 busy 或错误停止。D1 按 30 分钟时间段保存采集和发送游标，未完成任务下次续接，同一时间段不重复检查。不调用 `/api/refresh`，不等待资讯处理，不调用模型。

每个请求采集最多 4 个节目或处理 1 个读者；发送每请求最多 3 条，分批续跑，无新增不发消息。只推送关注时间之后、最近 7 天且未处理过的节目；静音、关闭提醒及未连接的读者不发送。热点/活动与节目共用发送租约，防止并发争抢与重复推送。旧小时任务与早晚采集任务保持暂停，每晚 21:00 的日更任务继续使用原入口。

完成后通过授权 GET `/api/subscriptions/refresh?status=1` 读回汇总进度，只报告 checked、failed、sent、phase，不读取或输出读者凭证、Webhook 或签名密钥。创建任务和部署成功都不等于实际执行成功，应以该状态及发送回执为准。

声动早咖啡的 Apple 官方当前 RSS 为 `https://www.ximalaya.com/album/51076156.xml`，本地检查返回 406；官网旧 Fireside RSS 只有截至 2023-10-17 的内容，不替换为这个停更源，也不计为当前已接通。

发布后须用服务访问凭证实际调用此写入接口并读回任务时间；保存定时任务不代表已执行，单元测试回执不代表真实飞书消息到达。

### 36氪 RSS 修复

官方订阅中心：`https://www.36kr.com/rss-center`。使用带 `www` 的 `feed-article` 和 `feed-newsflash`，分别获取文章与快讯，发布者统一为 `36kr`。裸域 `36kr.com/feed` 在本次环境返回安全检测页；`www` 的压缩响应虽含完整 RSS，curl 仍报传输错误，指定 `Accept-Encoding: identity` 后可完整读取。仅这两个来源设置 `uncompressed: true`；不跳过 TLS 校验，不使用登录 Cookie，不将阅读器缓存当作在线采集结果。线上是否成功以最新 `health` 为准。

## 资讯采集时间

北京时间（Asia/Shanghai）每天 21:00 启动一次统一更新。服务端 nightly_update 保存本轮日期和阶段，重复调用只续跑，同日完成后不再重新采集。资讯按 config/pipeline.mjs 的每批 4 个端点运行，失败保留旧内容和失败原因。读取本轮发布快照成功后，刷新榜单，再合并分区发送今日热点和活动提醒；节目更新独立每 30 分钟检查。早 8 点和晚 8 点的旧自动调用直接返回 skipped，不采集、不发送；云端定时任务须设为 21:00。

### 每晚更新与飞书分发

- 调度入口：POST /api/refresh，服务凭证只通过两种授权头传入，任务循环到 complete=true。GET /api/refresh 提供运行说明。busy、blocked 或 HTTP 错误须停止并记录，不绕过入口直接调用单阶段接口。
- news → models → subscriptions → complete 写入 D1；新闻本轮处理结束后冻结 nightly_publication。零星信源失败或预算耗尽不伪造完整数据，沿用已完成结果并返回 pending。
- 每日汇总分为今日热点、活动提醒两个区块，使用本轮已发布结果并尊重各类别开关；过长时拆成连续消息。热点按网站 hot 顺序，同条不重复；活动在首次发现、日程变更、开始/截止前 24 小时提醒一次，排除已结束/取消活动。日期不猜测、不补造。
- 每轮没有消息总量上限。每个 Worker 请求最多处理 3 条消息，然后续跑；节目查询每页 200 条，翻页直至全部处理。正文按 12 KB 分段，机器人请求至少间隔 1 秒。这些是单请求限制，不是每日上限。[飞书官方约束](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)：请求体不超过 20 KB，单机器人每分钟 100 次、每秒 5 次。
- 去重按读者与事件或节目 ID；排名变化不重发，单独归组的新进展可发送。未知回执不自动重试，发送记录保留待核对状态。机器人凭证加密保存，不出现在公开响应或日志。
- 网站「提醒设置」连接机器人，选择三类内容并开启提醒。仅保存 Webhook 不会开启推送。默认无需账户，设置跟随当前浏览器凭证。

## 热度趋势与来源图标

今日热点不展示数值分数，不提供来源/语言筛选。每轮采集完成且全部配置端点都在该轮检查过时，把事件去重报道热度保存到 D1 settings 的 news_trends_v1；保留7天，限制总大小，6小时内重复采集不追加趋势点。趋势使用原文 URL 别名关联，代表文章更换不丢失历史；曾拆分的事件取同一时刻最大的观测值，不相加。首次上线不回填推算历史；不足两个点显示“趋势积累中”，超过18小时的缺失不连线。排名继续采用既定综合判断，曲线单独反映报道热度。

来源真实图标位于 public/source-icons，官网及资产出处记录在 data/source-icons.json；脚本 scripts/fetch-source-icons.mjs 从官网声明的 icon 链接或 favicon 获取。浏览器只读取本站静态资源，缺失/加载失败显示来源名称，不生成字母头像。
